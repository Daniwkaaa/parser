# LeadFinder — пошук бізнесів, яким потрібна цифрова допомога

Вебзастосунок, який знаходить **реальні діючі бізнеси** (кав'ярні, салони, СТО, готелі, магазини, клініки тощо),
перевіряє їхню цифрову присутність (сайт, онлайн-меню, запис/бронювання, соцмережі, застарілість сайту),
рахує **Lead Score 0–100** і формує базу потенційних клієнтів для продажу послуг: сайтів, інтернет-магазинів,
QR-меню, систем онлайн-запису та бронювання.

> Жодних фейкових чи демонстраційних даних: усе, що показує інтерфейс, приходить із бекенду й отримано з
> реальних джерел. Якщо щось не вдалося перевірити — показується статус «Не перевірено».

## Можливості

| Розділ | Що вміє |
|---|---|
| **Головна панель** | Кількість бізнесів, без сайту, без онлайн-меню, перспективних, з перевіреними контактами; графіки за категоріями, потенціалом, проблемами, розподілом score; воронка статусів; останні пошуки |
| **Пошук** | Місто/район/радіус, **уся область** або **уся Україна** (лише підконтрольні території); кілька категорій одночасно; фільтри за типом проблеми або комплексний пошук; вибір джерел; кількість результатів; перевірка локації; хід збору та журнал у реальному часі; зупинка й продовження |
| **База бізнесів** | Таблиця з сортуванням за Lead Score, фільтри за категоріями, проблемами, потенціалом, статусом, сайтом і контактами; пошук за назвою, адресою, телефоном, email; зміна статусу прямо в таблиці; експорт відфільтрованої вибірки |
| **Картка бізнесу** | **Готове повідомлення** для Instagram/месенджера чи email з кнопками «Копіювати» та «Інший варіант»; усі дані й контакти, посилання на джерела, висновок, виявлені проблеми з поясненням, розбивка Lead Score, рекомендовані послуги, технічний аналіз сайту, міні-карта, нотатки, повторна перевірка, редагування контактів |
| **Карта** | Інтерактивна карта (Leaflet) з кольором за потенціалом і переходом у картку |
| **Налаштування** | Підкладка карти (темна/світла OSM без ключа або власний сервер тайлів); API-ключі (Google Places, SerpAPI) з поясненням, де їх взяти; джерела за замовчуванням; параметри пошуку; ваги й пороги Lead Score з перерахунком бази; експорт |

Додатково: **CSV і XLSX експорт**, **дедуплікація**, **збереження в БД** (дані не зникають після перезапуску),
**статуси клієнтів** (Новий → Укладено угоду), **нотатки**, **автоматичні рекомендації**, **відновлення перерваних пошуків**.

## Швидкий старт (Windows)

Потрібно один раз встановити:
- **Python 3.10+** — https://www.python.org/downloads/ (під час встановлення позначте *Add python.exe to PATH*)
- **Node.js 18+** — https://nodejs.org/ (потрібен лише для першої збірки інтерфейсу)

Далі:
1. Завантажте проєкт (`git clone https://github.com/Daniwkaaa/parser.git` або *Code → Download ZIP*).
2. Двічі клацніть **`start.bat`**.
   Перший запуск встановить залежності та збере інтерфейс (1–3 хв). Далі інтерфейс щоразу швидко перезбирається,
   тож після оновлення коду (`git pull`) достатньо знову запустити `start.bat`.
3. Браузер відкриється сам на **http://127.0.0.1:8000**.
4. Перейдіть у **Пошук** → вкажіть місто (наприклад, *Львів*) → оберіть категорії → **Почати пошук**.

macOS / Linux: `./start.sh`

### Ручний запуск (для розробки)

```bash
# Бекенд
cd backend
python -m venv .venv
.venv\Scripts\activate            # Windows  (macOS/Linux: source .venv/bin/activate)
pip install -r requirements-dev.txt
copy .env.example .env            # (macOS/Linux: cp .env.example .env)
python run.py                     # API: http://127.0.0.1:8000, документація: /docs

# Фронтенд з гарячим перезавантаженням (в іншому терміналі)
cd frontend
npm install
npm run dev                       # http://localhost:5173 (запити /api проксіюються на :8000)
```

Тести бекенду: `cd backend && python -m pytest` (25 тестів, включно з наскрізним сценарієм пошуку на локальних
тестових серверах — у робочу базу вони нічого не пишуть).

## Джерела даних

| Джерело | Ключ | Що дає |
|---|---|---|
| **OpenStreetMap / Overpass API** | не потрібен | Назва, категорія, адреса, координати, телефон, email, сайт, соцмережі, графік роботи. Основне безкоштовне джерело |
| **Nominatim (OSM)** | не потрібен | Пошук території (місто, район, область) |
| **Google Places API (New)** | ваш ключ | Рейтинг, кількість відгуків, сайт, телефон, посилання на Google Maps |
| **SerpAPI (Google Maps)** | ваш ключ | Те саме через SerpAPI; є безкоштовний місячний ліміт |
| **Публічні сайти бізнесів** | — | Аналіз головної сторінки та сторінки контактів (з дотриманням robots.txt) |

**Як отримати ключі**
- *Google Places:* [console.cloud.google.com](https://console.cloud.google.com/) → створіть проєкт → *APIs & Services → Library* → увімкніть **Places API (New)** → *Credentials → Create credentials → API key*. Потрібен платіжний акаунт Google Cloud (є щомісячний безкоштовний кредит).
- *SerpAPI:* зареєструйтесь на [serpapi.com](https://serpapi.com/) → *Dashboard → Your Private API Key*.

Ключі вставляються у **Налаштування → API-ключі** (зберігаються лише у вашій локальній БД) або у `backend/.env`.

**Етика та правила.** Застосунок не обходить авторизацію, CAPTCHA чи платні обмеження. Запити до Nominatim — не
частіше 1/с, до Overpass — з паузами та повторними спробами при 429/504, усі запити з ідентифікаційним
User-Agent (задайте свій контакт у `CONTACT_EMAIL` у `.env`). Сайти перевіряються лише в межах головної сторінки та
сторінки контактів і лише якщо це дозволяє `robots.txt`. Збираються тільки публічні ділові дані бізнесів.
Дані OSM © учасники OpenStreetMap, ліцензія ODbL.

## Як працює аналіз

Для кожного бізнесу:
1. **Нормалізація** — якщо в полі «сайт» вказано Instagram/Facebook/Taplink, це не вважається сайтом.
2. **Перевірка сайту** — доступність і HTTP-код, HTTPS, мобільна адаптація, рік у футері, CMS і версії бібліотек,
   ознаки онлайн-меню / каталогу / переліку послуг, віджети онлайн-запису та бронювання (Booksy, Altegio, DIKIDI,
   EasyWeek, Calendly, Helsi, Doc.ua, OpenTable, TravelLine, Bnovo, Exely та ін.), соцмережі, email і телефони.
3. **Статуси**: `Є` / `Відсутній` / `Лише соцмережі` / `Не працює` / `Не перевірено` / `Не застосовується`.
   Якщо сайт не перевірявся — проблеми не нараховуються.
4. **Проблеми** з поясненням (без вигадок — лише на основі отриманих даних).
5. **Lead Score** і **рекомендація** з переліком послуг.

### Lead Score (за замовчуванням, змінюється в налаштуваннях)

| Критерій | Бали |
|---|---|
| Немає власного сайту | +30 |
| Немає онлайн-меню / каталогу (для закладів харчування та магазинів) | +20 |
| Лише соцмережі замість сайту | +15 |
| Немає онлайн-запису / бронювання (для салонів, СТО, клінік, готелів, ресторанів) | +10 |
| Застарілий сайт або сайт-заглушка | +15 |
| Сайт вказано, але не працює | +15 |
| Є публічний телефон або email | +10 |
| Неповна інформація про бізнес | +5 |
| Сайт є, але є що покращити | +5 |
| Ніша з високим чеком (ресторани, готелі, клініки, салони, СТО, ремонт, фітнес) | +5 |
| Популярний бізнес: рейтинг ≥ 4.0 і ≥ 30 відгуків (дані Google Places / SerpAPI) | +5 |

Підсумок обмежується 100. За однакового score вище в списку ті, у кого є перевірений телефон чи email. **70–100** — високий потенціал, **40–69** — середній, **0–39** — низький.

### Типи проблем (фільтри)
Без вебсайту · Лише Instagram/Facebook · Сайт не працює · Без онлайн-меню/каталогу · Без онлайн-запису ·
Без системи бронювання · Застарілий вебсайт · Сайт є, але є потенціал для покращення · Неповна інформація.

### Виключення мереж
Опція «Виключати мережі» відкидає заклади з тегом `brand` в OSM, а також назви, що трапляються в межах пошуку
у двох і більше різних місцях (далі ніж 300 м одне від одного). Так відсіюються й локальні мережі, для яких
в OSM немає тегу бренду. Список виключених назв видно в журналі пошуку.

### Дедуплікація
Збіг за ID у джерелі; за телефоном (E.164) + схожою назвою або відстанню < 200 м; за назвою + відстанню < 150 м;
за назвою + нормалізованою адресою. Дані дублікатів **зливаються** (заповнюються порожні поля, додається джерело).

## Архітектура

```
backend/
  app/
    main.py              FastAPI, роздача зібраного фронтенду
    config.py            налаштування з .env
    db.py, models.py     SQLAlchemy (SQLite за замовчуванням, PostgreSQL через DATABASE_URL)
    categories.py        категорії ↔ теги OSM ↔ пошукові запити
    sources/             окремий модуль на кожне джерело
      base.py            інтерфейс BaseSource / RawBusiness
      osm.py             Overpass API
      google_places.py   Google Places API (New)
      serpapi.py         SerpAPI
      registry.py        реєстр джерел
    analysis/
      website.py         аналіз сайту
      evaluate.py        статуси, проблеми, Lead Score, рекомендації
    services/
      jobs.py            фонові завдання (потоки), проміжні результати, відновлення
      processor.py       дедуплікація + аналіз + збереження
      dedup.py, geocode.py, http.py (rate limit, тайм-аути, повтори), export.py, query.py, settings_store.py
    routers/             REST API
  tests/                 автотести
frontend/                React + TypeScript + Tailwind + Recharts + Leaflet
```

**Як додати нове джерело:** створіть `backend/app/sources/<name>.py` з класом-нащадком `BaseSource`
(метод `search(area, categories, limit, log) -> list[RawBusiness]`) і додайте його в `sources/registry.py`.
Воно автоматично з'явиться на сторінках пошуку та налаштувань.

**Надійність:** обмеження частоти запитів на хост, тайм-аути, повторні спроби з паузою, резервні сервери Overpass,
збереження кандидатів і прогресу в БД після кожного запису; якщо програму закрили під час пошуку — завдання
отримує статус «Перервано» і його можна **продовжити** з місця зупинки. Журнал: `backend/data/leadfinder.log`.

## Пошук по області та по всій Україні
Перемикач на сторінці пошуку: «Місто / район», «Уся область», «Уся Україна». Для області й країни застосунок
по черзі шукає в містах зі списку `backend/app/regions.py` (по одному запиту на місто, з паузами — так не
перевантажуються сервери OSM і не виникає тайм-аутів). Ліміт результатів розподіляється між містами: спочатку
обласні центри, далі менші міста. Проміжні результати зберігаються після кожного міста, тож пошук можна зупинити
й продовжити.

У список входять лише території під контролем України: окупованих Криму й Луганської області немає, а в Донецькій,
Запорізькій, Херсонській і Харківській областях взято тільки підконтрольні неприфронтові міста. Ситуація
змінюється — список легко відредагувати у `regions.py`.

## Готові повідомлення для бізнесів
У картці кожного бізнесу є блок «Готове повідомлення»: короткий текст для Instagram/месенджера або лист з темою
для email. Текст будується з виявлених проблем (немає сайту, меню, запису тощо) і рекомендованої послуги —
у нього не потрапляє нічого, що програма не перевірила. Кожен блок (привітання, вступ, факти, пропозиція, користь,
заклик) має кілька формулювань, тож різні бізнеси отримують різні тексти, а кнопка «Інший варіант» дає нове.
Ім'я, компанію, телефон, портфоліо й рід (писати від імені чоловіка чи жінки) задайте в **Налаштування → Готові
повідомлення**. Текст можна відредагувати перед копіюванням.

## Карта
За замовчуванням використовуються стандартні тайли OpenStreetMap (безкоштовно, без ключа) з темним CSS-фільтром.
У **Налаштування → Карта** можна обрати світлу версію або вказати власний URL тайлів (наприклад, MapTiler чи CARTO
з вашим ключем). Google Maps як підкладка не використовується: для цього потрібен платний ключ Maps JavaScript API,
а умови Google не дозволяють показувати дані з інших джерел на їхніх тайлах у такий спосіб. Посилання «Google Maps»
у картці бізнесу відкриває місце в Google Maps окремо.

## Обмеження та поради
- Повнота даних OSM залежить від міста: часто телефон і сайт вказані лише в чверті закладів. Статус «Відсутній»
  означає «не знайдено у відкритих джерелах». Для більшої повноти підключіть Google Places або SerpAPI, а в картці
  бізнесу є кнопки швидкого ручного пошуку в Google, Instagram, Facebook і Google Maps.
- Overpass інколи перевантажений (HTTP 429/504) — застосунок повторить запит і спробує резервний сервер.
- Для великих міст із багатьма категоріями пошук із перевіркою сайтів займає кілька хвилин (сайти перевіряються
  паралельно, але з обмеженням частоти).
